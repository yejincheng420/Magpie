## 2 用户已确认的需求

- 光标设置放在应用配置界面的光标区域，默认配置和独立应用配置都支持。
- 用户可以取消光标引起的高频额外呈现，并选择随原始内容帧更新。
- 静止画面或捕获暂停时保留可选的独立刷新。最低刷新率选项默认开启，默认值为 `60 FPS`，开启后允许用户修改数值。
- 两项设置是否合并由本次设计分析决定，见下一节。
- 继续允许 FG 效果的重复帧过滤参数覆盖主页全局设置，不统一成主页强制控制 FG。
- 主页开发者选项入口常驻，保留启用开关。
- 全局重复帧过滤选项常驻主页，不依赖开发者模式。

## 3 光标设置与调度规则

### 3.1 同组显示并保留独立控制

配置页使用同一个“光标刷新”设置组，保留两个独立控制，共用一个调度器：

| 控件 | 作用 | 默认值 |
| --- | --- | --- |
| 优先随原始内容帧更新 | 开启后不因移动光标或呈现生成帧而自动发布新光标位置；原始内容帧和启用的最低刷新期限负责更新 | 默认关闭，以保留旧配置的主要更新方式；这是本次设计选择，用户未指定此项默认值 |
| 保持光标最低刷新率 | 原始内容更新不足时，允许按设定目标补充发布变化的光标 | 开启，用户已确认 |
| 最低刷新率 | 上一项开启时可编辑，单位 FPS；关闭后禁用数值控件但保留数值 | 60，用户已确认 |

两项不能合成一个开关：第一项决定平时跟随哪些内容帧更新，第二项决定内容不足时是否允许补充更新。两项都开启时，UI 不能承诺“严格只随原始帧更新”或“完全没有额外呈现”；关闭最低刷新率后，才进入严格随原始帧更新的模式。

| 原始帧优先 | 最低刷新率 | 行为 |
| --- | --- | --- |
| 关闭 | 关闭 | 保留正常呈现时的光标更新，并允许移动引起的现有独立刷新；不提供额外最低频率保证 |
| 关闭 | 开启 | 保留正常呈现和独立刷新方式，内容不足时按设定目标补充；高内容帧率不会被限制到 60 |
| 开启 | 关闭 | 光标位置随新的原始内容帧发布，不由生成帧或光标移动请求额外呈现；静止或暂停时位置可停住 |
| 开启 | 开启 | 优先随原始内容帧发布；不足时按设定目标补充。生成帧可以承载到期补充，但不能无条件采样新位置 |

最低刷新率是目标下限，不是最高刷新率。示例：原始输入 30 FPS、DLSS 输出 120 FPS、原始帧优先开启且最低值 60 时，变化的光标按约 60 FPS 目标补充；原始输入 120 FPS 时仍可按 120 FPS 更新。该示例是调度目标，不是本轮实测结果。

### 3.2 原始帧定义

- “原始内容帧”指 Magpie 接受的新捕获帧所对应的非生成内容呈现，不等于游戏引擎内部真实渲染帧。
- 用捕获序列、资源代次和捕获帧 ID 区分内容身份；还必须检查 `generated` 标记。DLSS 生成帧可能携带与随后真实帧相同的捕获 ID，不能仅凭 ID 变化判定原始帧。
- 全局最低帧率重放、同帧参数更新和工具栏刷新不算新原始帧。FG 关闭像素去重后，相同画面的新捕获仍可能获得新身份；维持过滤选项本身的语义。
- XeSS 的生成帧由 SDK 代理交换链管理；原始帧更新点是成功提交的新基础内容帧，不假设 Magpie 能逐个接管 SDK 生成帧。

### 3.3 最低刷新率与输入处理

- 只有光标位置、形状、可见性等待发布状态发生变化时才安排补充，不对未变化或已隐藏的光标持续空呈现。自动隐藏到期、首次显示和重新进入捕获等可见性变化仍需处理。
- 补充期限从上次成功发布新光标状态计算。仅重画缓存光标、刷新工具栏或呈现生成背景不能重置期限；呈现失败时不得提交新状态和时间。
- 到期时优先让已有内容呈现承载补充更新；没有可用内容工作时才安排独立刷新。避免同一轮先呈现旧背景再呈现已就绪的新内容。
- 补充刷新不得调用后端效果链、制造捕获 ID、推进光流或 SR/NR 历史，或提交额外 FG 基础输入；普通和 DLSS 路径复用稳定的已呈现背景，XeSS 复用独立合成层。
- 调度目标受显示器刷新率、呈现容量和实际运行条件限制，不能承诺低刷新率显示器或阻塞状态下仍达到用户设定值。数值输入范围 `1–1000 FPS`，步长 `1`；保留有效小数，缺失、类型错误、非有限或越界值回落为 `60`。关闭最低刷新开关保留已保存的值。
- 一次停顿后只发布最新状态，不追赶堆积的光标帧。跨屏、DPI、尺寸变化和会话重启清理过期快照与期限。
- 保持鼠标输入、坐标变换、点击、捕获和命中检测的处理频率；限制视觉发布不能限制真实输入采样。工具栏拖动、参数编辑、点击和取消仍按既有输入调度响应。
- 工具栏普通刷新使用缓存光标状态，避免间接绕过原始帧优先。为进入界面、改变捕获归属、系统光标交接、截图隐藏等必要状态过渡定义明确例外。
- 单色或 XOR 光标可能依赖背景。背景变化时可以重新合成缓存位置和形状，不能因此无条件采样新位置；XeSS 背景依赖重绘也遵守这一规则。

## 4 主页与持久化规则

- 将“重复帧过滤”作为主页独立常驻卡片，保留现有“总是检测 / 动态检测 / 从不检测”三档，不在本任务中改变 Dynamic 算法或检测精度。
- 卡片说明明确：FG 效果的自身设置优先生效；没有 FG 时使用全局设置，普通 3D 游戏模式仍保留现有绕过行为。FG 参数缺失时继续沿用当前默认开启和兼容读取。
- 开发者入口常驻并保留启用开关。关闭时其他开发选项不可操作或折叠，入口仍保留；重新启用不需要关于页隐藏操作。
- 关闭开发者模式不再重置全局重复帧设置，保存后重启也应保持。其他开发选项沿用既有关闭规则，补齐常驻 UI 所需的属性通知，避免显示与模型不一致。
- 光标三项字段按应用配置保存，默认配置供未匹配应用使用。新增、复制、读取、保存、导入导出和旧配置缺失字段均要覆盖；默认最低刷新开启且为 60。
- 原始帧优先默认关闭是本次兼容性设计选择，最低刷新开启且为 60 是用户明确要求。旧配置缺少字段时沿用这组默认值。
- 默认和独立配置相互隔离，切换应用不共享运行期时钟或未提交光标快照。设置原则上在下一次启动缩放时加载，是否需要运行中即时应用不属于本轮已确认要求。
- 补齐英、简中、繁中资源及其他语言的既有回退，不因控件移出开发者区域破坏绑定、现有配置键或导入兼容。
