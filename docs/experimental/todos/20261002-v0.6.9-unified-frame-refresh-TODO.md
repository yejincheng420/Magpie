## 1. 用户确认的布局

- 默认配置与应用配置使用相同的“帧率与刷新”分组，紧邻图形与性能设置；所有字段独立保存到当前配置。
- 主页移除原“最小帧率”编辑入口，保留默认配置的刷新摘要和“编辑默认配置”入口。
- 原光标分组保留显示、大小、插值、自动隐藏和速度调整；刷新策略移到“帧率与刷新”，不保留重复的编辑入口。
- **节奏控制方式移出高级选项，放入内容帧率对应的展开区域，位于内容帧率选择下方、目标基础帧率上方。** 它是独立的下拉控件，不是内容帧率选择框里的选项。
- 高级选项只承接空闲持续重绘及其数值；高级组默认折叠。用户截图中的展开状态用于展示设置，不作为新增运行参数。
- 修改自动保存，重新启用缩放后生效。新建应用配置复制当时的默认配置；已有配置继续独立保存，不实时继承默认配置的后续修改。

```text

│  └─ 目标基础帧率             自定义时显示

```

显隐与编辑规则：

| 当前选择 | 节奏控制方式 | 相关数值 |
| --- | --- | --- |
| 内容帧率：跟随源 | 保留选择，但禁用固定目标节奏 | 隐藏目标基础帧率，保留已填数值 |
| 内容帧率：自动 | 显示并可编辑 | 隐藏手填基础帧率；按显示刷新率及补帧倍率计算目标 |
| 内容帧率：自定义 | 显示并可编辑，位于数值上方 | 显示目标基础帧率 |
| 光标：响应优先或仅随原始内容帧 | 不影响内容节奏选择 | 隐藏补充刷新率控件，保留其已填数值 |
| 光标：原始帧优先并补充 | 不影响内容节奏选择 | 显示补充刷新率；自动跟随可用显示刷新率，自定义显示最低值 |
| 空闲持续重绘：关闭 | 不影响其他选择 | 隐藏空闲重绘率并保留数值 |

## 3. 统一后的功能语义

### 3.1 内容帧率与节奏方式

- 跟随源：不主动配置固定基础帧率目标，仍受捕获能力、效果约束、呈现容量和 GPU 性能限制。
- 自动：沿用按显示刷新率和补帧倍率计算基础目标的规则，并响应显示器或倍率变化。
- 自定义：使用用户指定的基础处理目标；与节奏控制方式共同替代原独立“帧率限制”和“帧同步目标”编辑入口。
- Front Edge、Async、Reflex 继续保留各自的等待职责、能力判断和回退行为。XeSS FG 的基础节奏继续由 XeLL 接管；Reflex 不可用时沿用明确的回退规则。
- 每条基础处理路径只有一个有效限速责任方，避免重新叠加 StepTimer、呈现侧和 SDK 等待。
- `FrameRate_Filter` 跟随统一目标的行为保持一致；已有独立效果限制作为兼容约束处理，不生成新的互相竞争的目标入口。
- 内容目标不控制源应用自身的渲染速度，也不承诺提升源应用帧率。补帧后的输出与基础帧率分别表达。

### 3.2 光标策略

| 模式 | 行为 |
| --- | --- |
| 响应优先 | 光标状态变化即可请求更新，在可用呈现机会中按需发布 |
| 仅随原始内容帧 | 普通移动等待新的非生成内容帧；生成帧、旧画面重放和普通界面刷新不制造更新机会 |
| 原始帧优先并补充 | 优先使用原始内容帧，不足时按所选目标补充发布变化的光标 |

- 最低刷新率是补充目标，不是光标的最高刷新率；原始内容较快时允许随其更新。
- 只有位置、形状或可见性等待发布状态发生变化时才安排补充；未变化或已隐藏的光标不持续空呈现。
- 自动补充目标随显示刷新率变化，自定义值受实际显示与呈现能力限制。
- 保留首次显示、隐藏/显示、系统光标交接、窗口尺寸及坐标重建等必要状态转换。
- 原始内容身份继续使用捕获 ID、序列、资源代次及生成标记判定，不能仅凭相同或变化的帧 ID 判定。
- 游戏自己绘制进捕获画面的光标仍属于内容，不适用 Magpie 独立光标更新策略。

### 3.3 空闲持续重绘

- 将旧“最小帧率”改称“空闲持续重绘／空闲重绘率”，迁入当前配置。
- 没有新内容时按期限安排后端旧画面重绘；兼容未变化效果输出的复用及需要时间更新的动态效果。
- 有内容上限时，空闲重绘的生效值不高于该上限。用户保存值保持原样，显示限制原因；不能因运行时限速永久改写用户选择。
- 补帧期间继续停用后端空闲重绘，但保留其配置值；光标补充刷新仍独立生效。
- 文案说明可能增加功耗、不会提高源应用真实帧率；不将 GPU 频率稳定或减少卡顿写成已保证的效果。
- 捕获中断、尚无有效首帧或资源未准备好时，不以期限为由处理无效旧输入。

## 4. 刷新协调与呈现边界

- 新内容、光标变化、空闲重绘分别维护请求原因与期限，共用协调规则，并交给现有前后端执行。
- 有可呈现的新内容时优先合并光标与界面更新；避免同一轮先提交旧背景，再提交已就绪的新内容。
- 只有光标或界面变化时复用稳定的已呈现背景；不调用后端效果链、不制造新捕获 ID、不推进 SR/NR/光流历史、不提交额外 FG 基础输入。
- 光标期限只由成功发布变化状态推进；仅重画缓存光标、旧内容重放、工具栏刷新和呈现失败不能推迟期限。
- 内容限速默认约束内容工作，光标可以有更高的补充目标。修正普通 Front Edge 中光标重放参与基础时钟的问题，避免额外界面呈现推迟内容期限。
- DLSS FG 仍有共用呈现通道，XeSS FG 有独立叠加层；先基于现有路径协调内容与光标，不预先承诺所有后端都能达到独立目标，也不将新建 DLSS 合成层作为本轮必做项。

## 5. 配置与迁移

- 新模型保存内容模式、基础数值、节奏方式、光标模式、补充目标模式／数值、空闲模式／数值。具体字段和枚举名称在实施时确定；复制、恢复默认、读取及写入使用同一模型。
- 旧全局 `minFrameRate` 迁到默认配置及所有已有应用配置；已有新字段优先，迁移幂等，不能在每次启动时重新覆盖。
- 旧 `frameRateLimiterEnabled`／`maxFrameRate` 与配置级 `frontEdgeSync`／`frontEdgeSyncFrameRate`／`frameSyncMode` 联合迁移。关闭同步但有限帧、自动同步加独立上限，以及两者均为固定不同数值时，都要保留原有效约束。
- 自动目标与旧独立上限不能简单取一个固定最小值后丢弃自动语义；必要时保留迁移兼容约束，用户显式修改新入口时再更新。
- 旧光标四种开关组合迁入三个模式。两种响应优先组合中旧最低期限的细微差异需验证，必要时保留兼容状态，不能只合并标签后无声改变旧行为。
- 保留隐藏控件的已保存数值，避免切换模式、默认／应用配置或浮层保存时覆盖另一配置。
- 扩展配置恢复与范围校验：错误类型、非法枚举、非有限及越界值可靠回落；不能将正常的“关闭”和“自动”当成损坏配置。
- 配置迁移保留备份与恢复路径；不修改本轮实际运行配置。
- 运行时帧同步面板跟随同一配置模型，明确应用／重新启用行为，不能残留第二套独立目标或过期回调覆盖。

## 7. 关键验收场景

| 场景 | 预期 |
| --- | --- |
| 新配置默认状态 | 内容自定义 60、Front Edge、原始帧优先并补充、补充自定义 60、空闲启用 30 |
| 内容 30，光标补充 60，鼠标移动 | 按各自目标协调；光标补充不把效果处理或 FG 输入提升到 60 |
| 内容 120，光标最低 60 | 光标可随原始内容更新，不被最低值锁到 60 |
| 静止画面，鼠标不动，空闲关闭 | 不由光标或空闲配置发起持续空重绘 |
| 静止画面，空闲启用 30 | 保留有效旧输入，按空闲期限重绘；符合缓存／动态效果规则 |
| 内容上限 20，空闲保存值 30 | 生效空闲值受 20 约束，保存值仍为 30 |
| 启用 FG，空闲保存值 30 | 后端空闲重绘停用，光标按所选策略工作，退出 FG 后保留空闲设置 |
| 捕获中断、首帧未到或资源重建 | 保持已呈现有效画面，不制造无效新输入或错误历史推进 |
| 呈现失败或缓存光标重画 | 不提交新光标发布状态，不重置其补充期限 |
| 旧配置自动同步叠加固定上限 | 迁移后保留自动计算与旧上限，切屏／倍率改变后仍正确 |
