## 1. 结论

0.6.9 不照搬 Libretro `xbr` 目录中的全部历史文件。首批提供五个有明确差异、容易向用户解释的效果：

1. `xBR 2x`：标准 xBR LV2，固定 2×。
2. `xBR 3x`：标准 xBR LV2，固定 3×。
3. `xBR 4x`：标准 xBR LV2，固定 4×。
4. `xBR NoBlend 3x`：保留原调色板的 LV2 NoBlend，固定 3×。
5. `xBR Hybrid 2x`：xBR 与 Reverse-AA 的组合，面向已经带抗锯齿或平滑渐变的低分辨率 2D 画面。

`xBR LV3`、`xBR MLV4 Multipass` 和 `Super-xBR` 先做离线 A/B 与性能验证；只有相对首批效果存在稳定可见收益时，才加入 0.6.9 的公开效果目录。不要仅因上游存在对应文件就增加入口。

## 2. 上游基线与算法边界

### 2.1 固定参考版本

- 主要移植基线：[libretro/glsl-shaders `f8e23ff8`](https://github.com/libretro/glsl-shaders/tree/f8e23ff880668f0f0e837a05a316534d82a7f31b/xbr)。
- 语义和变体说明：[libretro/common-shaders `xbr/README.md` at `9c0d839a`](https://github.com/libretro/common-shaders/blob/9c0d839a19651dffc9898da7673574a20fb39415/xbr/README.md)。
- 算法原理：[Hyllian 的 xBR Algorithm Tutorial](https://forums.libretro.com/t/xbr-algorithm-tutorial/123)。
- 本地现有对照：`src/Effects/xBRZ/` 中的 xBRZ 2×～6×和 Freescale；xBR 不替换或重命名 xBRZ。

移植文件必须记录上游仓库、提交、原始路径、作者和许可证。标准 xBR LV2/LV3/MLV4 与 Super-xBR 参考实现使用宽松许可；Hybrid 同时包含 Hyllian xBR 的 GPL-2.0-or-later 声明和 Christoph Feck Reverse-AA 的 BSD 条款。项目本身为 GPL-3.0，仍须完整保留逐文件声明并更新第三方说明，不能只写一个仓库链接。

### 2.2 参考算法的实际含义

- LV1：只检测 45°、135°两个方向；属于基础版本。
- LV2：检测四个方向，是标准 xBR 的主入口；Blend 版本适用于整数倍率。
- LV3：检测六个方向，轮廓更圆滑，但计算量和误平滑风险也更高。
- MLV4：检测八个方向，并使用非贪心边缘选择；上游称其为标准 xBR 的后续演进，但它是四 Pass 路径。
- NoBlend：不混合新颜色，只从相邻像素选择颜色；可保持原调色板，但上游只推荐奇数整数倍率。
- Hybrid：xBR + Reverse-AA；用途不是替代标准 xBR，而是处理已平滑、已抗锯齿或带渐变的低分辨率素材。
- Super-xBR：把 xBR 边缘检测与线性插值结合，主要面向平滑渐变；属于独立的多 Pass 路线。

### P0：首批公开效果

| xBR 3x | `xBR\\xBR_3x` | `xbr-lv2.glsl` | 固定 3× | 标准 LV2 在奇数倍率下的重要对照，适合 240p/360p 等素材。 |
| xBR 4x | `xBR\\xBR_4x` | `xbr-lv2.glsl` | 固定 4× | 覆盖 240p→960p、270p→1080p 等常见整数链路。 |
| xBR NoBlend 3x | `xBR\\xBR_NoBlend_3x` | `xbr-lv2-noblend.glsl` | 固定 3× | 提供调色板保持路线，视觉结果与 Blend/xBRZ 有明确差异。 |

约束：

- `xBR 2x/3x/4x` 共用一份 LV2 核心函数，只保留三个很薄的输出倍率入口，避免复制三份算法主体。
- 不在首批增加 `xBR Freescale`。上游对标准 Blend 版本的建议是整数倍率；非整数最终尺寸由效果组中的后续缩放器处理，避免把未经验证的自由倍率包装成算法能力。
- `NoBlend` 首批只提供 3×。不提供 2×/4×，因为上游明确建议奇数倍率；5×只有在真实需求和 A/B 证据出现后再增加。
- `Hybrid` 首批只提供原生 2×。4×可以通过两次串联实现，但在确认重复执行不会明显放大伪影前，不创建独立 `Hybrid 4x` 入口。

如果上述门槛未满足，保留内部实验文件或调查记录，不加入效果选择器、内置效果文档和更新说明。

### P2：0.6.9 不加入

- `xBR LV1`：方向检测较少，除非性能测试证明它在低端 GPU 上形成有意义的独立档位，否则由 LV2 覆盖。
- `xBR LV2 Fast`：以质量换速度；先测标准 LV2，只有标准版本构成实际瓶颈时再考虑。
- `xBR LV1/LV2/LV3 NoBlend` 的全部倍率组合：只保留能体现“保持调色板”的 3×代表项，避免目录膨胀。
- `2xBR/3xBR/4xBR v2.x～v4.0`、`5xBR Retro` 等 legacy 文件：这些是历史迭代或特殊风格，不作为每个版本一个公开效果。
- `xBR LV2 3D`、`Super-2x/4x/8xBR-3D`：它们依赖内部像素分辨率和像素块启发式，并不读取游戏深度或可靠地区分 2D/3D。对任意窗口捕获容易误判，名称也可能让用户误以为具有真正 3D 内容识别。
- `Deposterize`、`Smart Blur`、`Dilation`、CRT 组合预设：属于多效果组合或历史实验，不混入本轮 xBR 基础效果。
- 同一算法的 `small-details`、`adaptive` 独立副本：优先做成参数；只有参数无法表达不同 Pass 拓扑时才考虑独立入口。

## 4. 参数与用户可见行为

### 4.1 标准 xBR LV2

保留上游默认值，首批公开以下参数；同一组参数在 2×/3×/4×保持一致：

| 参数 | 上游默认 | 产品语义 |
| --- | --- | --- |
| `Y Weight` | 48 | 调整亮度差在颜色距离中的权重。 |
| `Eq Threshold` | 15 | 判断相邻颜色是否相近的阈值。 |
| `Lv2 Coefficient` | 2.0 | 陡线/浅线判断强度。 |
| `Preserve Small Details` | Off | 减少小眼睛、点状高光和 1 px 特征被连接或磨圆。 |

- 参数 ID 沿用上游稳定名称，中文只做解释，不发明新的算法术语。
- 如果内部测试发现前三个技术参数对普通用户难以安全调整，可在公开目录只保留 `Preserve Small Details`，其余固定为上游默认；决定须写入实施记录。
- 固定倍率属于效果输出合同，不做运行中倍率参数。

### 4.2 NoBlend 与 Hybrid

- 标准 LV2 不公开 `Lv1 Coefficient`：固定上游文件虽然声明了该参数，但当前算法路径没有读取它，避免制造无效设置。
- NoBlend 首批只公开 `Lv2 Coefficient`；所选上游 Corner A 路径不读取 `Eq Threshold`，因此不暴露无效参数。输出颜色必须来自采样到的源颜色集合，禁止无意加入线性过滤。
- Hybrid 首批不开放 Gamma 常量。参考 Shader 假定 gamma-coded SDR 输入；HDR/scRGB 或线性输入必须明确拒绝、走已验证的颜色转换边界，或在单独验证后提供等价路径。
- 所有效果保持 Point 采样、正确的边界夹取和源 alpha；不得像旧 Shader 那样无条件输出 alpha=1。
