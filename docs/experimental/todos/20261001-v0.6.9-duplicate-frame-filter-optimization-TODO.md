## 1. 初始审查问题与证据边界

| 项目 | 初始基线行为 | 处理方向 |
| --- | --- | --- |
| 上游输出变化未完整传播 | `inputRevision` 在上游实时参数更新时递增；SMAA 时序效果按每次后端渲染的 `FrameCount` 更新相位及历史。强制旧帧重绘时，捕获 ID 不变，后续 DLSSNR 可能命中旧输出缓存 | 统一每个效果的输出版本与历史推进规则，变化传递到全部后续消费者 |
| 时序超分重复执行旧输入 | 强制重绘仍调用 DLSS / FSR / XeSS SR；Frame Guidance 只在接受新捕获帧时更新，因此同一帧的旧运动信息会再次交给 SDK | 未变化的旧输入复用已完成输出；参数或上游输出变化走明确的重算与历史失效路径 |
| 精确检测同步读回 | GPU 比较后立刻以 `D3D11_MAP_READ`、flags 为 0 读取 staging 结果；可能等待 GPU 完成相关工作 | 测量等待与过滤收益，再评估保留纹理的有界异步方案 |
| HDR 前置处理开销 | HDR 捕获转换发生在重复比较前；当前比较对象是原始捕获纹理 | 评估在颜色语义和资源有效性可确认时，将精确比较提前 |
| Dynamic 放行窗口 | 检查与跳检交替，最多连续跳过 16 帧检查；跳检阶段即使统计检测出重复也继续放行 | 保留抽查语义，量化漏检与无效处理；不宣传为逐帧完全去重 |
| RGB 判断范围 | 精确比较 RGB，忽略 Alpha；微小 RGB 变化也算新内容 | 明确 Alpha 和颜色元数据合同；保持精确比较，不默认加入模糊阈值 |

前两项的执行路径和缓存条件可从源码确认，但具体拖影、闪烁或画面延迟尚未实测。当前没有证据证明普通有效 RGB 画面的比较算法普遍把不同内容误判成重复。同步等待点可以确认，当前耗时和是否构成主要瓶颈仍需受控测试；历史日志不代替 0.6.9 测量。

## 2. 保留的运行语义

| 条件 | 有效捕获过滤模式 |
| --- | --- |
| 存在 DLSS FG / XeSS FG，`duplicateFrameFiltering=1`，默认开启 | Always，覆盖全局设置及 3D 模式 |
| 存在补帧，`duplicateFrameFiltering=0` | Never，覆盖全局设置 |
| 无补帧，3D 游戏模式开启 | Never |
| 无补帧，3D 游戏模式关闭 | 使用全局 Always / Dynamic / Never，默认 Dynamic |

- 保留全局枚举、补帧参数键、默认值、效果组保存和重启生效规则；优化不增加额外模式或运行状态面板。
- 首个有效输入与捕获中断后新序列的首帧必须放行，即使像素相同，也要让消费者得到恢复后的资源及历史重置。
- 没有新捕获帧、检测到内容重复、捕获中断、参数更新要求重算分别处理，不能仅用一个 `Waiting` 状态推断全部原因。
- 捕获中断期间保留最后有效输出，参数更新不能强行推进无效输入；无首帧时不处理未定义的纹理内容。
- 补帧继续只接受有效的新基础输入；旧帧重绘不得伪造新的捕获 ID、重复提交旧运动信息或增加补帧任务。
- 光标、工具栏和参数面板保留独立刷新能力；无需重算图像效果时仍能正常交互。
- FrameRate_Filter、最大 / 最低帧率和 Front Edge / Async / Reflex / XeLL 的调度职责保持清楚，去重不另建第二套限帧器。

## 4. P1 修正效果链版本传播

推荐在 Renderer 中维护统一的效果输出版本，由它传递到后续输入。版本应在输出可能变化时更新，不因单纯的前端刷新或缓存复用而更新；同时保留效果自身参数版本。

- [x] C01：建立输入版本、参数版本、输出版本与重算原因的共同合同。覆盖普通 shader、动态 / 时序 shader、原生 SDK、HDR / SDR 转换及自动追加的尺寸处理。
- [x] C02：上游实时参数更新、有效的新捕获输入、时序输出更新和会影响颜色结果的资源 / 颜色语义变化，均使对应下游输入失效；无需改变像素的限帧参数不误伤图像缓存。
- [x] C03：修复 `SMAA T2x / 4x → DLSSNR` 等同帧组合。只要上游输出变化，NR 不得因捕获 ID、自身参数版本和旧输入版本相同而早退。
- [ ] C04：缓存条件包含实际输入版本、参数版本、资源身份 / 代次、尺寸 / 格式和历史重置代次；使用引导时检查相关引导绑定、有效区域及 Zero / fallback 状态。不能把纹理指针相同当作内容相同。
- [x] C05：多层 DLSSNR 保留每层缓存及后续层失效传播。配合重复资源开销 TODO 的 C02 / C03，明确链内 NR 版本、出口残差版本和外部抗闪烁版本；不在两个方案中重复维护互相矛盾的缓存键。
- [ ] C06：验证纯 Residual 参数更新只重做实际受影响的输出处理；如果它改变了当前逐层串联中后续 NR 的输入，仍必须使后续层失效。不能在新出口合同实施前提前删除现有传播。
- [ ] C07：失败、fallback、resize、效果重建、停止重开和设备更换完整失效；缓存只能引用生命周期有效、GPU 写入依赖已满足的结果。

## 5. P1 统一旧输入重绘与时序历史

推荐默认规则：旧输入且图像参数未变化时复用效果链输出，只刷新需要更新的呈现或叠加层。参数或上游结果变化时，从首个受影响效果开始重算，并明确历史处理；捕获 ID 保持真实来源，不能通过递增 ID 绕过缓存。

| 场景 | 图像效果处理 | 时序与补帧 |
| --- | --- | --- |
| 新接受的有效捕获输入 | 按依赖执行效果链 | 各消费者按新输入推进；按需要提交补帧 |
| 无新内容，图像参数不变 | 复用有效输出，按原调度需要呈现 | 不推进图像历史；不提交旧输入补帧 |
| 同捕获帧的参数 / 上游输出变化 | 重算受影响阶段及必要下游 | 受影响历史按版本失效；不重复使用上一对帧的运动关系 |
| 捕获中断 | 保留最后有效输出 | 不重算无效捕获，不推进历史 |
| 新捕获序列首帧 / 资源重建 | 放行首帧或重新生成有效输出 | 重置必要历史，重新验证缓存和引导 |

- [x] T01：SMAA T2x / 4x 及 NoJitter 变体按有效新输入推进相位与历史；旧输入复用不再次写入历史纹理。保持相位初始化和采样序列可复现。
- [x] T02：明确一般动态 shader 的依赖：时间动画确实需要变化时允许执行，并传播新的输出版本；不要把所有 `_DYNAMIC` 效果一律冻结。
- [x] T03：为 DLSS / FSR2 / FSR3 / FSR4 / XeSS SR 建立同输入、同参数的输出复用。旧输入不重复执行 SDK，也不重复消费上一次非零运动向量。
- [ ] T04：同捕获帧但参数 / 输入变化时验证各 SDK 的重算合同，选择有证据支持的 reset、历史快照或其他安全路径；仅改为零 MV 不自动证明历史正确。历史重置按受影响版本执行，下个新捕获输入使用新产生的引导。
- [ ] T05：检查 RTX Video VSR / Denoise / HDR 和诊断效果的实际依赖，允许未变化输入复用；保留参数立即刷新、颜色转换正确性与失败处理。
- [x] T06：DLSSNR 与外部防闪烁使用一致的输入版本。同输入复用时不推进 EMA 时间或历史索引；输出控制变化仍刷新防闪烁所消费的结果并清理必要历史。
- [ ] T07：保留最低帧率所需的输出刷新和 UI 响应，避免为更新 FPS / 光标而重新执行整条 SDK 链；补帧现有旧输入提交保护继续生效。

## 6. P2 优化精确检测与读回

同步读回替换属于待测候选。不能仅删除 `Map` 等待或增加 `DO_NOT_WAIT` 后使用旧结果；检测结果必须对应将要接受或过滤的那张纹理。

- [ ] D01：为 Always / Dynamic / Never 建立相同输入与处理链的对照，分别测试几乎全重复、几乎全变化及混合输入；统计节省的处理量、读回等待分布、GPU 时间和显示延迟。
- [ ] D02：评估有界的比较任务 / staging 环。每个槽关联被比较的输入、历史基准、捕获序列、资源代次和完成状态；保留纹理或不可变快照直到判断结束，不让第 N 帧结果应用于已覆盖成 N+1 的纹理。
- [ ] D03：验证非阻塞查询、结果未就绪时的等待 / 保守放行策略及任务顺序。明确延迟、显存和最大在途数量，保留背压；收益不足或增加不可接受延迟时保留同步实现。
- [ ] D04：首帧、捕获恢复、资源变化和在途任务取消保留正确放行与清理；比较初始化失败或读回失败时不使用陈旧的“重复”标志。诊断记录失败原因并沿用既有设备错误处理。
- [ ] D05：仅当捕获 API 的证据足以证明内容未变化时，评估直接复用；时间戳或纹理句柄相同不能单独替代内容证明。WGC / DXGI / GDI / DWM 路径分别验证。
- [ ] D06：复核全分辨率比较、边缘覆盖、采样坐标和历史纹理复制成本；优化仍使用精确内容合同，不能通过默认容差忽略文字、光标外 UI 或小范围更新。
- [ ] D07：保留 CPU 等待与 GPU 计算时间的分别记录，降低普通构建日志频度；统计开关的额外比较开销单独标明。

## 7. P2 HDR Alpha 与 Dynamic 边界

- [ ] H01：明确各捕获源的 Alpha 是否有意义及是否影响最终输出。有意义的 Alpha 变化纳入内容变化判断；恒定或未定义的捕获 Alpha 不盲目用于去重，输出仍遵循已有 Alpha 合同。
- [x] H02：检查颜色描述、转换参数、有效区域或资源代次变化时的失效。RGB 相同不保证经过新的颜色语义处理后输出相同。
- [x] H03：评估把原始捕获比较移到 HDR 转换之前。重复输入仅在已有 canonical 输出有效、颜色语义和资源未变化时跳过转换；恢复首帧、resize 和参数重算仍生成匹配的 canonical 输出与元数据。
- [ ] H04：RGBA / BGRA、SDR UNORM / HDR FP16、负值 / 高光、奇数尺寸及非有限值分别验证；非有限值处理与当前颜色管线合同一致，不能用误判重复隐藏无效内容。
- [ ] Y01：保留 Dynamic 的抽查定位，记录跳检放行重复输入的数量及后续无效 SDK 工作。降低跳检上限或改变策略仅作为受控候选，不预设更频繁比较一定更快。
- [x] Y02：验证跳检结束时历史基准更新、重复后重新进入检查、捕获序列变化和统计开关。统计模式不悄悄改成 Always，也不宣称零漏检。

## 8. 验收用例与完成标准

| 场景 | 必须验证的结果 |
| --- | --- |
| 完全相同的有效 RGB 输入，Always | 除首帧 / 恢复等必要例外外正确过滤；后端不持续重复推理 |
| 单像素、边缘像素、每个 RGB 通道的微小变化 | 精确模式接受有效变化，含奇数和非线程组对齐尺寸 |
| Dynamic 的检查与最长跳检窗口 | 放行与过滤符合实际策略；统计能区分漏检和有效新内容 |
| SMAA T2x / 4x / NoJitter → DLSSNR，源画面暂停，最低帧率大于 0 | 未变化旧输入不推进历史；任何实际上游输出变化都刷新 NR |
| DLSS / FSR2 / FSR3 / FSR4 / XeSS SR，None / AMDOF / NVOF，运动后暂停 | 不重复将旧运动向量用于旧输入；无新增拖影或闪烁 |
| 同帧连续修改上游参数、各层 NR 参数及 Residual 参数 | 立即刷新必要输出，复用仍有效的阶段，历史与版本正确失效 |
| 光标移动、工具栏、参数面板和 FPS 更新，静止输入 | UI 正常响应；无不必要的 SDK 重算或补帧提交 |
| 补帧开关、过滤开关、全局三模式与 3D 模式组合 | 优先级、默认值、保存 / 重启生效和基础帧提交符合合同 |
| WGC / DXGI / GDI / DWM，SDR / HDR 支持路径 | 捕获源等待与内容重复分别处理，格式和颜色正确 |
| 捕获中断恢复、resize、设备失效、比较初始化 / 读回失败 | 无旧结果错配、死等、资源提前复用或首帧被错误过滤 |

- [ ] V01：使用生产判断路径测试版本传播、分类、任务对应关系和失败处理；用实际生产 shader 的软件渲染测试验证像素覆盖与格式合同，不能用实现镜像测试代替。
- [ ] V02：使用真实 SDK / GPU 验证时序历史、参数重算、读回 / 槽复用和资源生命周期；检查 D3D 调试层，CPU 替身或软件渲染通过不代表此项完成。
- [ ] V03：分别对照“当前基线”“仅正确性修复”“读回候选”“HDR / Dynamic 候选”。记录处理次数、缓存命中、CPU / GPU 耗时分布、1% Low、显存及输入到显示延迟，并保存逐帧画质证据。
- [ ] V04：完成相关回归、Release x64 构建、配置兼容和文档检查；按真实验收结果更新清单，未测项保持未勾选。
- [ ] V05：每项性能候选给出实施并验证，或前提不成立 / 收益不足保留原行为的结论。正确性问题不得仅以关闭过滤、关闭时序效果或降低画质作为默认修复。

实施顺序：P0 基线与分类 → P1 版本传播与旧帧时序规则 → P2 读回、HDR 与 Dynamic 候选。先交付正确性修复，再逐项评估性能，避免同时改动后无法定位收益或退化。
