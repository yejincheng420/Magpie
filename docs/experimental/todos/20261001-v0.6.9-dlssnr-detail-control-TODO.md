- 使用 Oklab 作为新残差精细控制的基础，修复现有 HSL 灰轴着色与整条 RGB 残差方向切换问题。
- 将前面讨论的全部项目纳入本 TODO：现有控制整理、四项新增保护／压缩、大范围与细节修正、色度时域稳定、自动色域压缩，以及精度、抖动、升采样、诊断和验收。
- 新控制的最终中文名称为 **色相变化保护**、**局部失控压缩**；产品 UI、效果目录、参数说明、测试和后续更新说明使用这两个名称。
- Residual 总倍率扩展为 `0–2`，允许完整关闭当前帧总修正；现有“饱和度”在新模式中改为 **色度变化强度**。

保护类参数统一按“`0=关闭保护，1=最强保护`”设计。因此 **色相变化保护默认 0**，内部对应色相变化增益从 1 逐渐减弱。这个默认值用于保持原始 NR 修正，与前述增益型提案的方向不同；不沿用旧提案的“默认 1”。局部失控压缩同样默认 0。

## 2. 已知问题与必须保留的合同

### 2.1 诊断确认的问题

- 候选颜色在灰轴上返回任意 Hue=0，随后恢复原图部分饱和度，导致突然着色。WARP 测试中候选 `(127,128,129) → (128,128,128)`，输出约 `(89,128,167) → (166,90,90)`。
- 按线性亮度差正负选 Shadow／Glow 倍率，再缩放整条 RGB 残差。混合色度残差跨越零亮度差时，候选 G 只变化 1 个色阶，可使输出 R 跳变约 10 个色阶。
- 精确零亮度差使用倍率 1，还可能与非 1 的左右倍率形成孤立异常点。
- 候选／HSL／最终输出的多次裁切、近黑／近白 HSL 饱和度敏感性、RGBA8 量化和 Catmull-Rom 负瓣会叠加色带、层次压平或边缘过冲。
- CPU 模型与 WARP 证明了上述边界问题；尚未用真实问题帧确认各因素占比，尚未验证新算法的 NVIDIA GPU 成本和视频画质。

### 2.2 基础合同

- 细节控制处理所有 NR 完成后的**总残差**，参考最初推理尺寸输入 `L0` 与最终推理尺寸输出 `LN`。与开销优化 TODO 协同，统一处理一次。
- 保留原尺寸输入作为最终基底；残差控制在升采样前执行，升采样对象继续是有符号浮点 RGB 差值。不能把 Oklab 差值直接加到 RGB 原图上。
- 总倍率 0、当前总残差 0 时输出原图；原 alpha 不受细节控制影响。
- 总倍率及各现有增益为 1、新增保护／压缩关闭、频率增益为 1 时，结果应保持同一原始 NR 候选的中性输出。新 Oklab 往返只允许有界数值误差，不新增默认色偏或额外限幅。
- 默认快速路径与参数略偏离默认值的路径必须连续，不能在默认点附近突然启用另一套色域映射。
- 调整纯输出控制复用有效 NR 结果，只更新残差处理和必要重建；按既有规则使外部抗闪烁历史失效，防止旧强度继续混入。
- Residual=0 时抗闪烁历史不得延续先前修正；此前残差变为 0 时也要明确并验证当前帧归零／历史清除规则，不仅验证静态函数的零残差。
- 新方案首先覆盖启用输入分辨率调整的 SDR 路径，包括比例 100%。开关关闭及实验 HDR FP16 路径沿用各自合同；HDR 扩展另做格式与颜色空间验收。

## 5. P1：Oklab 残差与两处断层修复

- [x] C01：统一 SDR 传递函数、线性 RGB ↔ Oklab 转换、有限值检查和中性路径。明确 shader 工作域，避免 UNORM SRV 与手动解码重复转换。

## 6. P2：四项新增保护／压缩

### 6.1 色相变化保护

- [x] H01：将色度残差按原图色度方向分成径向与改变方向的分量，保护优先抑制后者，保留明度和必要色度大小变化。
- [x] H02：接近灰色时连续淡出色相保护，使用正则化向量投影／连续权重，不引入原图或候选色度的硬阈值。
- [x] H03：覆盖有限残差导致色度向量反向、穿过零色度、Hue 环绕和高饱和边界。保护强度 1 也不能因径向过冲造成 180° 反色；不能把投影近似宣传成所有情况下精确锁 Hue。
- [ ] H04：验证保护 0 等价于关闭该保护，0→1 单调增强，滑块连续变化无颜色跳跃；观察肤色、天空和彩色光源。

### 6.2 暗部保护与高光保护

- [x] P01：定义基于原图 Oklab L 的连续掩码及过渡宽度，强度 0 完全关闭；不用黑白区间的硬分段开关。
- [ ] P02：暗部保护限制黑位漂移、深暗部染色与微小噪声放大；明度／色度的保护比例先做 A/B，避免抹掉真实暗部细节。
- [ ] P03：高光保护结合原图明度和颜色到输出边界的余量，减少近白着色、过曝及亮部层次压平；正／负修正分别验证，不能阻止应保留的高光恢复。
- [x] P04：掩码参考原图／固定基线，不依赖本次受控输出反复重新分类，避免参数反馈与顺序改变。

### 6.3 局部失控压缩

- [x] K01：以 Oklab 残差幅度或明确加权的感知差定义强修正，采用连续软拐点；参数 0 关闭，小修正尽量保持原样。
- [x] K02：优先统一缩放残差向量，避免独立 RGB 硬上限产生额外偏色；核对与明度／色度增益、色相保护和色域压缩的顺序。
- [x] K03：初版使用像素级软压缩。若引入局部邻域统计，使用边缘感知／稳定统计并测量资源开销，避免把邻域硬门限变成新的断层。
- [ ] K04：验证单个异常修正、连续渐变、真实强对比和强彩色光源，明确压缩并不等于恢复原始细节或保证 NR 判断正确。

## 10. 验收清单与执行顺序

推荐执行顺序：基线与迁移 → Oklab／断层修复 → 四项保护／压缩 → 自动色域压缩 → 频率／时域进阶 → 精度与升采样评估 → UI／配置／实际画质与性能验收。与开销优化的资源链共用规划，功能变化与资源重构分别留对照。

- [x] V01：生产 HLSL 编译及 CPU／WARP 对照，覆盖灰轴两侧、精确灰色、ΔL 过零、混合符号残差、极暗／极亮、Hue 环绕与色域边界；误差阈值按实际纹理精度定义。
- [x] V02：连续像素扫描与连续滑块扫描，分别检查值跳跃、斜率变化、平台／裁切和量化色带；默认点、保护启用点及所有分类边界必须覆盖。
- [x] V03：中性组合、总倍率 0、零残差、频率互补、保护关闭、Legacy 配置和新配置完整回归。
- [ ] V04：真实静帧 A/B：低饱和渐变、肤色、天空、深暗部、近白高光、彩色光源、UI／字幕、细线及不同尺寸／比例／pass 数；保存原图、NR 输出、受控残差和最终图。
- [ ] V05：真实视频 A/B：静止渐变、缓慢镜头移动、快速运动、遮挡、修正消失和连续调参，检查颜色闪烁、拖色、历史清除和抖动颗粒。
- [ ] V06：必要单元／shader／配置回归、Release x64 构建与 HLSL 严格编译；原生参数 GUI、DPI、多显示器与保存／还原另行验收。
- [ ] V07：记录目标 NVIDIA GPU 的默认、保护开启、频率开启与色度稳定开启的 CPU／GPU 时间、纹理／dispatch、显存及初始化开销；不得用 WARP 时间代替真实 GPU 性能。
- [ ] V08：更新实施记录，逐项注明已实施／已验证／未验证。完成必要检查后再整理 069 分发材料，构建成功不自动等同于已部署或画质通过。
