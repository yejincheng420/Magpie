## 已实施行为

应用配置的光标组新增“优先随原始内容帧更新”和“保持光标最低刷新率”两个开关，以及可编辑的最低 FPS。默认原始帧优先关闭，最低刷新开启、60 FPS。范围为 1–1000，异常值回落 60，关闭时保留数值，下次启动缩放生效。默认配置、应用配置、复制和配置序列化使用同一组字段：`cursorPreferOriginalFrames`、`cursorMinimumRefreshEnabled`、`cursorMinimumRefreshRate`。

| 原始帧优先 | 最低刷新 | 光标发布方式 |
| --- | --- | --- |
| 关闭 | 关闭 | 保留随正常呈现更新和既有移动触发的独立刷新 |
| 关闭 | 开启 | 保留上述方式，同时用独立光标期限保证按需补充 |
| 开启 | 关闭 | 新的非生成捕获内容帧更新；移动和生成帧不请求额外更新 |
| 开启 | 开启 | 优先新的非生成捕获帧，不足时按最低期限补充变化状态 |

最低值是目标下限，不是上限；原始内容 120 FPS 不被最低 60 限制。独立刷新受显示刷新率、帧同步和呈现容量限制。首次绘制、隐藏/显示、系统光标交接、工具栏移动光标角色变化以及尺寸/坐标重建是必要例外；因此严格模式取消的是普通移动引起的额外呈现。游戏画面内自绘的光标仍属于捕获内容。

`CursorRefreshPolicy` 用帧 ID、捕获序列、资源代次和生成标记区分原始内容，并分离输入采样、待绘制快照与成功发布状态。生成帧、旧内容重放和普通工具栏刷新按策略使用缓存光标；单色/XOR 光标在新背景上重新合成缓存位置。自动隐藏使用真实输入活动时间。只有成功发布变化状态才推进光标期限，失败不推进；光标绘制资源失败而表面提交成功时，下一轮重建视觉状态。

普通和 DLSSFG 补充刷新复用稳定的已呈现背景，内容/FIFO 优先；XeSSFG 使用现有独立 DComp 层。XeSS 成功提交但光标未变化时消费原始帧身份，不进行空的 UI 提交，也不让后续移动借用已经消费的旧原始帧。补充路径不制造捕获 ID、不调用后端效果链或 FG SDK 基础帧提交。DLSSFG 仍共享内容呈现通道，独立光标合成层留作后续测量评估。

主页重复帧过滤三档已移出开发者区域，FG 参数优先、缺省默认开启及普通无 FG 的 3D 绕过规则保留。开发者入口常驻，关闭时折叠/禁用开发控件并保留开关；其他开发选项沿用关闭规则并通知 UI，全局重复帧设置不再被重置。补齐英、简中、繁中资源，其他语言使用既有 en-US 回退。

## 069 beta1 交接验收

1. 编译完整产品并验证原生配置页：旧配置默认关闭/开启/60，四种组合，数值编辑和关闭保留值，默认/应用配置隔离；验证主页开发者开关、过滤三档、关闭后保存/重启，以及 FG 覆盖提示。
2. 在普通效果、DLSSFG 2/3/4 倍和 XeSSFG 可用倍率验证静止、暂停、恢复、低/高内容帧率；覆盖 3D 模式、重复帧过滤开关、不同显示刷新率和帧同步容量限制。
3. 验证窗口/全屏、跨屏/DPI/尺寸变化、拖动、参数输入、自动隐藏、截图、彩色及 XOR 光标；确认普通界面刷新使用缓存坐标，必要的可见性/归属交接仍响应。
4. 在启用 FrameTrace 的验证构建比较 `CursorPublish`（`a=新原始帧机会`，`b=独立 UI 层`）、`OverlaySubmit`/`DcompCommit`、`ContentSubmit`、`CaptureAccepted`、`FgQueued` 和 SDK 输入计数。`CursorPublish` 只记录成功发布变化状态，含初次和归属/可见性变化，不记录缓存重画；它不是 GPU 计时。
5. 对比 CPU/GPU 开销、光标延迟、额外呈现次数和 FG 吞吐，记录容量限制及收益；未变化/隐藏时不应有由光标持续发起的空呈现。按测量结果决定是否另开 DLSSFG 独立合成层开发。
