# 069 Reflex 标记边界修正

日期：2026-10-02。开发分支：`feature/069-reflex-marker-boundaries`；基线：`experimental` 的 `118b1add`；合并目标：`experimental`。

本次完成源码修正、针对性测试与语法检查。069 beta2 产品编译、部署及真实 GPU 验收由单独会话执行。

## 捕获端

原先 `BeginCapture()` 在取帧前同时发送 Simulation / Render 开始标记。捕获返回 Waiting 后保留候选，因此静止窗口、重复时间戳、像素重复或捕获恢复等待会使 Render 区间一直开放。

现在 `BeginCapture()` 只负责一次 Sleep、候选 ID 和 Simulation 开始。四种捕获方式在实际纹理工作前调用 `BeginCaptureRender()`：WGC 和 Desktop Duplication 在有效纹理复制前，DWM Shared Surface 在打开共享资源前，GDI 在获取目标表面 DC 前。无 GPU 工作的取帧轮询保留候选，不反复 Sleep，也不开 Render 区间。无新纹理但确需重算效果时，Renderer 在效果工作前开启区间。

像素比较等 GPU 工作之后仍被拒绝的输入，在本轮结束时关闭并丢弃该候选；下一次尝试使用新的单调 ID。捕获中断与错误在等待 / 退出前结束候选。Front Edge 暂存 DLSS FG 输入时，在提交效果 GPU 工作后关闭 Render 区间，保留候选与 Present ID 分配到 FG 完成，不把输入期限等待算进 Render，也不重复 Sleep。

被拒绝的候选可能使 Reflex / NGX / 引导帧 ID 出现间隙。Renderer 额外向 native 效果传递上一张实际接受的捕获 ID；NR 防闪烁据此确认运动历史对应关系，避免把合法 ID 间隙误当成遗漏的有效输入。确实跳过有效输入、历史代次变化、资源变化、运动有效性变化和时间戳异常仍按既有规则失效。未提供前驱 ID 的调用方保留原连号判断。

等待时间仍可能出现在 Magpie 自身的 Simulation / 捕获阶段；这些标记不代表源游戏的模拟或输入采样。

## 前端

原先 `_UpdateFrontendBase()` 复制基础纹理后，`AdaptivePresenter::BeginFrame()` 才发送异步 Render 开始，基础、参考与运动纹理工作在区间之外。

现在 AdaptivePresenter 先通过 `PrepareFrame()` 获取交换链容量令牌；令牌由既有 `FrameLatencyGate` 保存，之后 `BeginFrame()` 复用它。容量不足直接返回外层消息循环，没有纹理复制或 Render 开始。

有效共享槽通过资源 / 序列检查后，在槽锁保护下读取不可变 Reflex / Present ID，随后开启 Render，再创建和复制基础、参考与运动纹理。`BeginFrame()` 不重复开启同一区间；现有绘制和 Present 前结束标记继续使用该槽的 ID。失败退出和 resize 关闭已开启的区间，不制造 Present。旧帧浮窗刷新使用零内容 ID，DComp 路径继续暂停 DXGI Reflex。其他呈现器保留原有 BeginFrame 容量 / SDK 调用流程。

## 069 beta2 交接

真实 NVAPI / NGX、硬件捕获、GPU 跨设备归属和端到端延迟没有在本次测量。自动测试与 WARP 不证明延迟或 FPS 改善。

beta2 会话从合并后的 `experimental` 编译部署后，优先核查：

- 普通 Reflex 与 DLSS FG 2x / 3x / 4x，WGC 静止 / 恢复、重复时间戳、Always / Dynamic 像素过滤：无 GPU 工作时 Render 不开放，拒绝的 GPU 尝试在下一次等待前结束，ID 仍单调一致。
- Front Edge + DLSS FG 暂存输入：期限等待在 Render 结束后，候选与输出 ID 保留；相邻有效 NR 运动输入跨 ID 间隙时历史不误重置。
- 前端容量不足、资源忙、旧槽、resize、DXGI / DComp 切换及独立浮窗刷新：开始标记先于共享复制，正常提交只有一对，失败 / 切换不残留区间或伪造内容 Present。
- 同条件对照基线与修正：记录帧率、捕获到显示延迟、CPU / GPU 队列、容量等待及标记时段；特别观察提前容量准入对吞吐与延迟的影响。

本会话不构建或替换产品运行包、不发布 Release。
