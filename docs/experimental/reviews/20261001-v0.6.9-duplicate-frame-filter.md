## 行为变化

- Renderer 为每个效果维护完成输出的内容版本和独立历史代次。缓存键包含捕获 ID、上游版本、参数版本、捕获序列、资源代次以及输入 / 输出纹理身份、尺寸和格式。内容版本变化使下游重算；普通新帧不因此清空时序历史。
- 最低帧率、光标 / 浮窗刷新或未改变图像的参数更新遇到有效旧输出时，跳过 shader、HDR 边界转换及 native SDK 工作。仍按已有调度发布 / 呈现，补帧旧输入提交保护保留。FrameRate_Filter 和未启用的 NR 层参数不使图像版本失效。
- 四种 SMAA T2x / 4x 效果只随接受的捕获事件推进相位，旧输入复用不再次写历史。重算时参数 / 输入 / 资源变化清理历史纹理；一般 `_DYNAMIC` shader 保留渲染时钟，每次执行产生的新版本传给下游。
- DLSS / FSR2 / FSR3 / FSR4 / XeSS SR 在必须重算旧捕获输入时使用零运动引导及 SDK reset。旧 ZeroMV / Jitter / OpticalFlow 路径也接收重置信号，本地光流重置历史，旧帧重新执行复用原采样相位。
- 与新的 DLSSNR 集中调度合同结合：NR 先使用捕获引导判断缓存 / 总残差重建；只有必要 SDK 重算才切换到 Zero 并 reset。纯 Residual 更新不因切换引导而额外执行 NR。外部防闪烁区分内容版本与历史代次，避免每个正常新帧都把 EMA 权重降为零。
- 失败输出不成为可复用缓存；SDK marker 回退仍更新下游版本并保留重试。resize、重建和中间结果导出使受影响缓存失效，防止复用已被改写的纹理。
- 原始捕获比较移至 HDR 转换之前：仅当 canonical 输出有效且颜色语义不变时过滤并跳过转换。完整颜色描述变化即使 RGB 相同也放行并推进资源代次。resize 清空 canonical 后从已有捕获重建，并用接受帧的序列、资源代次、时间及颜色重新生成引导；保持真实捕获时间；无首帧不制造有效内容。
- HDR 保留 Alpha，因此比较包含 Alpha；SDR 延续 RGB-only。比较 shader 使用组内归并和原子发布差异标记，保持精确通道比较。初始化失败清理全部部分资源，读回失败保守接受当前输入；比较 SRV / UAV / CB 在后续复制和 HDR 处理前解绑。

全局 Always / Dynamic / Never、3D 模式、FG 覆盖优先级、参数键、默认值和重启生效规则均保持原合同。捕获 ID 表示接受的事件；Never 与 Dynamic 跳检不保证像素唯一。

## 可观测性

Frame Trace 新增 `CaptureClassification`、`RenderReason`、`EffectReuse`、`EffectExecute` 和 `HdrCapture`。关闭 Frame Trace 时使用既有空实现，不增加 UI 面板。

- `CaptureClassification.a` 为 `CaptureFrameReason`：0 接受，1 无帧，2 中断，3 像素重复，4 Dynamic 跳检，5 未过滤，6 新序列，7 颜色语义变化，8 初始化不可用，9 读回失败，10 错误；`b` 为捕获序列。
- `RenderReason.a`：0 新捕获，1 最低帧率刷新，2 参数 / 导出要求重算，3 resize。`EffectReuse / EffectExecute.a` 为效果索引，后者 `b` 表示输入历史需重置。
- `DuplicateReadback` 保留 CPU 等待记录；普通汇总日志改为每 1200 个样本输出平均 / 最大等待。Frame Trace 的嵌套 CPU 时段有重叠，不能相加当作 GPU 时间。比较 GPU 时间和端到端延迟仍需单独性能验收。
